# 抽取準確度標註集（golden set）

用來回答一個問題：**改了抽取規則之後，到底有沒有變準？**

沒有這份標註，調 `extractors/rule_engine.py` 的黑名單、補 `data/alias_dictionary.json`
都只是憑感覺——你不會知道修好一個案例的同時弄壞了三個。

```bash
.venv/Scripts/python -m pytest backend/tests/golden -s
```

`-s` 會印出逐案例表格，以及每一筆漏抽／亂抽的實際字串。

## 怎麼新增一個案例

一個案例兩個檔，檔名相同、副檔名不同：

```
data/golden_set/<案例名>.txt        文件原文，直接從 Word 貼過來
data/golden_set/<案例名>.expected   應該要抽到的引用，一行一筆
```

`.expected` 的格式：

```
# 井字號開頭是註解，會被忽略
政府採購法	第70條
政府採購法施行細則
CNS 3090
```

- 條號可以不寫。**沒寫就代表不在乎**，不會被檢查——標註成本低一點。
- 分隔可以用 TAB 或連續兩個以上空白（從 Word 貼過來常常會變成空白）。
- 名稱比對前會走 `clean_text()`，全形／半形、書名號、條號差異都不算錯。

**有 `.txt` 沒有 `.expected` 會直接讓測試報錯。** 安靜跳過等於讓人以為標註做完了，
而分數會因為樣本變少而失真。

## 匿名化

這個目錄**進版控**，所以貼進來之前請先把專有名詞換掉：

| 換掉 | 換成 |
|---|---|
| 業主／機關名稱 | ○○機關 |
| 標案名稱、標案編號 | ○○工程 |
| 廠商、監造單位名稱 | ○○公司 |
| 人名、聯絡方式 | 刪除 |

法規引用本身不是機密，把專有名詞換掉之後就可以安全進版控。
換掉這些字**不會影響量測**——抽取器看的是法規名稱，不是業主是誰。

## 記得也放反例

只放「有引用的段落」會有個陷阱：把黑名單全部刪光，recall 反而變好看。

所以要放**整段都不該抽到東西**的文字——日常用語（「施工方法」「無法取得」）、
泛稱（「相關規範」「本節說明施工規範」）。`.expected` 留空（或只有註解）即可。
`negative-01-common-words` 就是這種案例。

## 量到的範圍

只量抽取層（文字 → 候選），不量整條 檔案 → 引用清單：

- 要調的是抽取，解析器的問題是另一回事，混在一起看不出是誰的錯
- 幾毫秒就有結果，可以邊補標註邊看數字
- 測試環境關閉 AI，**只有規則與字典兩層被量到**，數字是確定性的
  （LLM fallback 只在前兩層都沒收穫時才啟動）

比對層（引用 → 對到哪一部法規）不在這裡量，那是另一組指標。

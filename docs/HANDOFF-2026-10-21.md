## 4. 必須保留的資料語意

1. 圖說候選不自動成為工程結論；沒有標單時不得確認配對或宣稱標單缺項。
2. 所有圖說修改帶 `expected_revision`。遇到 409 必須重新讀取並核對，不自動重送決策。
3. 名稱分組與近似提示不自動合併；同名不等於相同位置或可以合併工程量。
4. AI 轉錄使用 `assisted`，保留原文、頁碼、來源與限制，不冒充人工核准。
5. 索引重建會替換指定文件的圖頁／候選與覆核；不可為了刷新畫面而重建。
   標單重建也會使既有配對失效。先備份，保留使用者的人工欄位。
6. 整合與核對 GET 不重建、不寫入決策。工法候選不能作為施工指示。
7. 歷史核對成果須與專案、文件雜湊綁定；不載入任意路徑或其他專案成果。
8. 契約文件優先順序必須來自本案確認，不套用先前另一案的契約條款。

## 5. 接手後如何啟動

在獨立 checkout 或空白開發資料庫操作；已有資料時先依 [備份說明](local-backup.md) 備份。
從本分支建置的新環境不能假設本機私人資料已隨 Git 交付。

Windows PowerShell，在專案根目錄：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
npm ci --prefix frontend
```

僅在尚無 `.env` 時複製 `.env.example`，保留既有設定。供本機離線測試的設定：

```dotenv
DATABASE_URL=sqlite+aiosqlite:///./data/app.db
ENABLE_LLM_FALLBACK=false
REGULATION_SOURCES=mock
ALLOWED_EXTENSIONS=.docx,.pdf,.txt,.xls,.xlsx
```

`mock` 只供測試。要啟用官方來源，先執行以下兩個同步命令，成功後將
`REGULATION_SOURCES` 改成 `taiwan_law,pcces`，再確認 `/api/sources`：

```powershell
.venv/Scripts/python.exe scripts/sync_taiwan_law.py
.venv/Scripts/python.exe scripts/sync_pcces.py
```

建立資料表與啟動：

```powershell
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

另一個終端：

```powershell
npm run dev --prefix frontend
```

前端預設 `http://localhost:5173`；若後端換埠，可在前端環境設定
`API_PROXY_TARGET=http://127.0.0.1:新埠號`。操作入口是「專案工項」。
圖框 OCR 另裝 `requirements-ocr.txt`；Linux 容器操作見 [local-backup.md](local-backup.md)。

新建專案後上傳自己的測試 PDF，指定契約圖角色並建立索引即可驗證圖說流程。
沒有私人核對成果時，歷史成果區會顯示缺少資料；這是預期降級，不是安裝失敗。
`create_drawing_inspection_manifest.py` 只綁定既有成果，不會自動生成完整逐頁核對。
還原後成果路徑目前僅可由服務建構參數指定，尚無環境變數入口。

- 同案標單：取得後建立工項，驗收真實配對、來源差異及數量欄位；目前停止搜尋。
- 本案契約、施工規範全文與適用版本：需提供或確認，竣工圖不能自行視同契約原版。
- 人工覆核：候選工項、目錄差異、引用適用性、近似項合併及工法選定，均保留。
- 不進行自動工程量計算或安全／施工適用性判定。

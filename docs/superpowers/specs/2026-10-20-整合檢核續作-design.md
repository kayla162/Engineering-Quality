# 整合檢核續作設計

使用者已授權依建議順序完成不需標單或人工判斷的工作，保留人工標註。
本文件記錄本次實作選擇；不再要求同一工作範圍的重複批准。

## 範圍與成功條件

1. 建立官方公開法規及 PCCES 本機索引，查詢驗證後才切換本機來源；不重跑既有分析或覆核。
2. 新增唯讀整合檢核 API 與介面，合併既有標單、圖說聯集及規範依據。
3. 同一份整合資料支援 XLSX、CSV、PDF 匯出，包含來源、證據、人工狀態與限制。
4. 將既有本機圖說核對成果以專案限定方式呈現，提供名稱分組、目錄／引用疑義及原圖。
5. 提供工法候選與待確認流程：僅從明確文字取候選，未經人員選定皆為未指定，不從外型猜測。
6. 補上 Docker OCR 選配、備份還原工具及驗證紀錄；可用環境內完成實測。

## 邊界

- 原有 drawing_sheets、drawing_items、work_items、work_item_bases、regulation_references 逐欄保留。
- 不呼叫重建圖說／標單／檢核表，不自動確認、排除、合併、配對或改名。
- 目前 1,447 筆圖項全 pending；無標單仍可檢視和匯出候選，不能宣稱缺項。
- 舊 Checklist API 保持相容；新增 integrated-checklist API，圖說及依據狀態各自呈現。
- `OK` 只表示規範依據狀態，不升格為全面合規；契約優先順序須依本案契約確認，禁止套用別案條文。
- 外部同步只下載公開資料，工程 PDF、證據、資料庫留在本機；不啟用 LLM 或付費 API。
- 不部署、推送或合併；本輪修改留於現有功能分支，原有未提交修改保留。

## 介面與資料

新增 `GET /api/projects/{project_id}/integrated-checklist`，唯讀回傳：
`project_id, revision, total, summary, warnings, contract_note, items`。
每列包含 `key, work_item_id, item_no, name, source_status, basis_result,
chapter_code, chapter, bases, drawings, method`。
drawings 保留候選 id、文件 id／檔名、頁碼、圖號、圖名、原文、review_status／review_note。
key 以 `work:<UUID>` 或 `drawing:<UUID>` 穩定識別，配對後同一圖項可出現在多工項列。
method 包含 `status: unspecified|pending`、候選文字與來源；本輪不新增人工決策寫入 API。
未有明確工法候選仍顯示「未指定」，相關圖號就是人工後續查閱入口。
`GET .../integrated-checklist/export?format=xlsx|csv|pdf` 使用相同組裝服務。

核對成果使用專案／文件雜湊綁定的 manifest；只有白名單 JSON 及裁切影像可讀，
禁止任意 filesystem path／跨專案讀取。缺少成果時顯示未建立，不影響整合表。
人工核對狀態來自目前 DB；歷史報告只展示當時 AI 整理，明確標示快照版本。

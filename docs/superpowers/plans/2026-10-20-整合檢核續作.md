# 整合檢核續作 Implementation Plan

> 使用 subagent-driven-development，依工作責任分派實作與審查；root 負責資料來源與整合驗證。

**Goal:** 完成不依賴同案標單或人工判斷的整合功能，保存既有資料。
**Architecture:** 保留既有 API，新增唯讀整合服務與專案限定的核對成果服務；匯出及 UI 共用資料。
**Tech Stack:** FastAPI / SQLAlchemy / SQLite、React / TypeScript、openpyxl / reportlab。
**Spec:** `docs/superpowers/specs/2026-10-20-整合檢核續作-design.md`

## Global Constraints

- 不重建或更動既有人工欄位，不自動工程判定，不傳送私有資料至外部。
- 無標單不等於缺項；工法未經人工選定不標為指定；來源失效顯示缺資料。
- 現有 feat/stage2-drawings 已為獨立功能分支；不另複製未提交成果、不自動提交或推送。

## Review Focus

- 舊人工決策保留與純 GET 沒有寫入。
- 多對多圖項不漏列，拒絕跨專案資料。
- 匯出內容與畫面一致，公式字首與 HTML／路徑輸入安全。
- 歷史核對成果明確標示版本，不冒充最新人工狀態。
- 無標單、無規範、無成果時仍可操作。

- [x] 2. backend agent：新增 integrated_checklist schema/service/routes、工法候選純函式與三種匯出；先寫失敗測試，實作後跑相關測試。
  產出上述 spec 的完整 JSON 契約；不改既有 Checklist schema 的結構。
- [x] 3. inspection agent：新增專案綁定成果 manifest、唯讀 API、安全影像服務及測試；產出前端可消費的小型清單與白名單影像路由。
- [x] 4. root 實作／delivery agent 修正：依 2/3 已定契約新增整合表、篩選／搜尋／匯出／工法與核對成果頁塊，保留既有人工表單；元件測試與 build。
